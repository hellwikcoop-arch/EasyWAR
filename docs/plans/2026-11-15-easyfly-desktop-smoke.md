# КРОК 2 / Gate-01 — EasyFLY desktop smoke (Windows і macOS)

**Статус:** сценарії підготовлені 15.11.2026; ручний прогін **ще не виконано**.
**Рішення JE:** почати КРОК 2 із desktop smoke. **Перед релізом повторити на фінальних артефактах обох ОС**; провал хоча б одного критичного сценарію означає `NO RELEASE`.
**Пов'язано:** [issue #260](https://github.com/hellwikcoop-arch/EasyWAR/issues/260), [release checklist](../RELEASE_CHECKLIST.md), [WORKSPACE.md](../WORKSPACE.md), [EasyFLY source](../../src/workspace/easyfly/app.js).

## Підготовка

- [ ] Запустити **реальну desktop-збірку** Tauri 2, не браузерний preview. Зафіксувати commit SHA, архітектуру/версію OS, ім'я та SHA-256 артефакту. Використовувати **тільки синтетичні дані**.
- [ ] Створити два окремі тестові профілі A/B (один із паролем), без особистої інформації. Не використовувати робочу базу EasyWAR.
- [ ] Виконувати на **Windows** та **macOS** окремо; не робити висновок про обидві ОС з Linux CI.
- [ ] Для технічних збірок доступний вручну `workflow_dispatch` у `.github/workflows/desktop-build.yml`: він запускає збірку macOS/Windows з runner і технічний launch smoke; релізні сертифікати/нотаризація перевіряються окремо.
- [ ] Якщо немає доступу до ОС чи артефакту, ставити `NOT RUN`, а не `PASS`.

**Додатковий тест погодних/AI-гейтів КРОКУ 1:** із [issue #260](https://github.com/hellwikcoop-arch/EasyWAR/issues/260): погода без дозволу/після відмови збереження → нема дозволеного outbound, явно підтверджений онлайн → працює; нативне підтвердження завантаження моделі — «Ні» без HTTP, закритий профіль/чуже вікно не ініціюють download. Для desktop smoke **не потрібно** реально завантажувати 2,5 ГБ моделі або звертатися до платних AI API.

## Автоматизовані тести, що доповнюють manual smoke

- `npm run test:unit` — чисті редуктори `fly-state.js`, валідація та круговий обхід `serialize → parse` тестуються в `tests/easyfly-app.test.mjs`, `tests/easyfly-core.test.mjs`.
- `node --test tests/easyfly-save.test.mjs` — тестова черга запису: snapshot перед `unmount`, порядок записів, помилка сховища з повтором, демо без збереження, синтетичний `create → edit → flight → save → parse → reopen`.
- Файлові unit-тести **не замінюють** запуск Tauri і не доводять надійність операції під час реального завершення процесу.

## Приймання

**Gate-01 PASS** лише коли обидві desktop-платформи пройшли критичні EF-01…EF-12, плюс перевірки погоди/AI КРОКУ 1, з exact SHA. Для релізу **повторити** smoke на фінальних встановлюваних артефактах та заповнити [production checklist](../RELEASE_CHECKLIST.md). До цього статус **NO RELEASE**.

**Поточне обмеження:** `unmount` може лише поставити асинхронний запис у чергу; фізичне завершення процесу одразу після зміни може зірвати запис. Тому EF-05 — окремий обов'язковий desktop-тест. Не приписувати успіх, поки не отримані фактичні результати.
