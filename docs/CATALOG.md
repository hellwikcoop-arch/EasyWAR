# Каталог стовпців, плиток і блоків (формат v1)

Статус: **крок 1 з 4** конструктора таблиць (дорожня карта — нижче). Є лише формат і
суворий валідатор: `src/catalog-core.js`, тести `tests/catalog-core.test.mjs`. Застосунок
каталог поки не читає, поведінка дашбордів не змінилась.

## Навіщо

Нині набір стовпців, шість карток «Основних показників» і 14 блоків дашборда ПС зашиті в код
`air.html` (те саме, з відмінностями, — у `rocket.html`). Каталог переносить їх у **дані**:
нова колонка, плитка чи вид журналу — це запис у JSON, а не правка сторінки. Код потрібен
лише для нового *типу* віджета (наприклад, діаграми Ганта).

Двигун не знає предметної області. Він працює зі **стовпцями певних типів** і
**підрахунками** над ними, тому однаково описує журнал ударів і журнал польотів бригади.

## Принципи

- **Дані, а не код.** У файлі немає виразів, формул, скриптів і посилань. Плитка — композиція
  з фіксованих частин: підрахунок × стовпець × відбір × вигляд.
- **Три шари:** `builtin` (вбудований) → `owner` (власника) → `profile` (профілю). Каталог
  шару посилається на свій шар і нижчі. Ідентифікатори не повторюються між шарами:
  власний варіант вбудованого елемента — це **новий id** з `based_on`, а не перевизначення.
  Тож оновлення застосунку не затирає чужих правок.
- **Недовірений вхід.** Каталог можна принести файлом з іншого комп’ютера. Валідатор працює
  закрито: невідомий ключ, зайвий тип, посилання в нікуди, керівний чи bidi-символ у підписі,
  перевищення ліміту — помилка, а не мовчазне виправлення. Успіх дає новий **заморожений**
  об’єкт лише з дозволених ключів.
- **Межі гнучкості (свідомі):** без мови формул і скриптів, без зв’язків між таблицями.
  Тип стовпця — із фіксованого набору.

## Ідентифікатори

Малі латинські літери, цифри, `.`, `_`, `-`; до 64 символів; обов’язковий префікс виду:

| Префікс | Що |
|---|---|
| `cat.` | сам каталог |
| `list.` | список значень |
| `col.` | стовпець |
| `tile.` | плитка |
| `block.` | блок дашборда |
| `kind.` | вид журналу |

Підписи, назви й значення — звичайний текст до 80 символів (ліміти кожного поля — в
`LIMITS`). Керівні, невидимі й bidi-символи відхиляються; текст нормалізується до NFC й
обрізається по краях. Порівняння підписів на дублікати (`foldLabel`) не розрізняє регістр,
пробіли й варіанти апострофа (`'` `’` `ʼ`).

## Структура файлу

```
{ format: "easywar.catalog", version: 1, id: "cat.…", title, layer,
  lists?: [list], columns?: [column], tiles?: [tile], blocks?: [block], kinds?: [kind] }
```

Невідомі ключі скрізь — помилка. `version` вищий за підтримуваний дає окрему помилку
`unsupported_version` («створено новішою версією застосунку»).

### Список значень `list`

`{ id, title, values: [{ value, label?, aliases?: [..] }], allowCustom?, based_on? }`

Від 1 до 500 значень. `value` і `aliases` не повторюються між собою (з поправкою `foldLabel`).
Якщо `allowCustom` не `true`, значення у відборах стовпців цього списку мають входити до нього.

### Стовпець `col`

`{ id, type, labels, aliases?, group?, description?, unit?, list?, min?, max?, integer?, maxLength?, based_on? }`

| Тип | Значення в клітинці | Додатково |
|---|---|---|
| `text` | текст | `maxLength` |
| `number` | число | `unit`, `min`, `max`, `integer` |
| `date` | дата `рррр-мм-дд` | |
| `time` | час `ГГ:ХХ` | |
| `duration` | тривалість у `unit` | `unit` обов’язковий: `хв` або `год`; `min`, `max`, `integer` |
| `choice` | одне значення зі списку | `list` обов’язковий |
| `multichoice` | кілька значень зі списку | `list` обов’язковий |
| `flag` | так / ні | |
| `coordinates` | координати (MGRS) | лише перевірка на наявність у відборі |

`labels` — від 1 до 8 **запропонованих варіантів заголовка**; перший — типовий. `aliases` —
додаткові назви для зіставлення (до 16). Усі `labels` та `aliases` стовпця різні. Ключ, який
не застосовується до типу (наприклад, `list` у тексту), — помилка.

### Підрахунок `measure`

`{ agg, column?, filter?, by?, grain? }`

| `agg` | Що повертає | `column` | Додатково |
|---|---|---|---|
| `count` | кількість записів | заборонений | |
| `share` | частка записів, що пройшли відбір | заборонений | `filter` обов’язковий |
| `sum`, `avg`, `max`, `min` | підсумок за числовим стовпцем | `number` або `duration` | |
| `distinct` | кількість різних значень | будь-який, крім `coordinates` | |
| `top` | найчастіше значення | `text`, `choice`, `multichoice` | лише як додатковий показник плитки |
| `peak` | найбільший підсумок за добу, тиждень чи місяць | необов’язковий числовий (без нього — кількість записів) | `by` (дата) і `grain` обов’язкові |

**Відбір** `filter` — від 1 до 8 умов `{ column, op, value? }`, з’єднаних «і». Операції: `eq`,
`ne`, `in`, `notin`, `gt`, `gte`, `lt`, `lte`, `empty`, `notempty`. `gt…lte` — лише для чисел,
тривалостей, дат і часу; `empty`/`notempty` — без `value`; для координат дозволені лише вони.
Значення перевіряється за типом стовпця: число, дата `рррр-мм-дд`, час `ГГ:ХХ`, булеве для
`flag`, а для `choice` — ще й належність до списку.

### Плитка `tile`

`{ id, label, sub?, measure, per?, visual, by?, tone, delta?, icon?, extras?, opens?, based_on? }`

- `visual` — одна з наявних у дашборді форм: `bars` (стовпчики за місяцями; до одного
  додаткового показника), `ring` (кільце частки; потрібен `share`, без `per` і `extras`),
  `pair` (лінія й пара міні-плиток; рівно два `extras`). `bars` і `pair` малюють ряд за датою,
  тому потребують `by` — стовпця дати.
- `per` — друга міра, на яку ділиться перша («наліт на борт»).
- `delta` — що вважати добрим: `up`, `down`, `warn`, `neutral`; зміну до попереднього періоду
  можна рахувати лише за `by`.
- `tone` — один із шести тонів палітри дашборда (`blue`, `amber`, `green`, `orange`, `red`,
  `grey`). Довільних кольорів немає, щоб зберегти єдиний вигляд.
- `icon` — лише ідентифікатор (`plane`, `bomb` …); невідомий малювальник підставить типову.
- `extras` — до двох показників `{ label, measure }`.
- `opens` — блок, куди веде кнопка «Докладніше».

### Блок `block`

Ключі залежать від `kind`; зайві ключі — помилка.

| `kind` | Обов’язкові | Необов’язкові |
|---|---|---|
| `tiles` | `tiles` (1–12 плиток) | |
| `dynamics` | `by` (дата), `measure`, `grain` (`day`/`week`/`month`) | |
| `breakdown` | `by` (текст, вибір, кілька, прапорець), `measure`, `shape` (`bars`/`ring`/`top`) | `limit` (1–50) |
| `heat` | `by` (час), `measure` | `across` (дата) |
| `map` | `coordinates` | |
| `table` | `columns` (1–30) | |
| `quality` | — | |

Підрахунок блоку: `count`, `sum`, `avg`, `max`, `min`, `distinct`.

Блок `tiles` — ряд плиток. Сьогоднішній блок «Основні показники» (`p-kpis`) має такий самий
вигляд, а окрема плитка як окремий блок — це блок `tiles` з однією плиткою.

### Вид журналу `kind`

`{ id, title, description?, sheet, columns: [{ column, core?, default? }], tiles?, blocks?, layout?, based_on? }`

- `sheet` — назва аркуша (до 31 символу, без `\ / ? * [ ] :`, не починається й не закінчується
  апострофом, не «History»).
- `columns` — стовпці, які пропонує вид; `core` — не можна прибрати, `default` — позначений
  одразу.
- `tiles`, `blocks` — що пропонує вид. Усе запропоноване має бути **досяжним**: стовпці, які
  читає плитка чи блок, входять до `columns` виду. Блок `tiles` містить лише плитки, які
  пропонує вид.
- `layout` — типова розкладка тієї самої форми, що й у рушії «Розташування блоків»:
  `{ rows: [{ cols: [{ w, cards: [block…] }] }] }`; до 20 рядів, до 4 колонок, `w` від 0
  до 12, кожен блок не більше разу й лише з `blocks` виду.

## Обмеження

Файл не більший за 512 КіБ; не більше 200 списків, 300 стовпців, 300 плиток, 100 блоків,
50 видів; не більше 50 повідомлень про помилки (далі `truncated: true`). Усі значення —
в `LIMITS` у `catalog-core.js`.

## Програмний інтерфейс

- `parseCatalogText(text)` → `{ value, error }`: розмір, BOM, коректність JSON.
- `validateCatalog(input, { base })` → `{ ok, errors: [{ path, code, message }], truncated, catalog }`.
  `input` — об’єкт або текст; `base` — уже перевірені каталоги нижчих шарів (лише результат
  `validateCatalog().catalog`, інакше `TypeError`).
- `tileColumns(tile)`, `blockColumns(block, findTile)`, `measureColumns(measure)` — які стовпці
  потрібні, щоб конструктор міг вимикати плитку чи блок із поясненням.
- `foldLabel(text)` — ключ порівняння підписів.

## Що ще не вирішено

- **Формат v1 не заморожений.** Крок 2 (шість поточних карток як описи) може показати потребу в
  нових підрахунках, наприклад «кількість діб періоду» для «Середнього темпу».
- **Порівняння значень у відборі** (регістр, пробіли, апострофи) визначить крок обчислень;
  `foldLabel` зараз використовується лише для пошуку дублікатів.
- **Тривалість у клітинці XLSX** — число в одиницях `unit` чи формат «години:хвилини» — вирішить
  крок запису таблиці.
- **Де лежить каталог профілю й розкладка.** Нині розкладка дашборда ПС зберігається в
  `localStorage` під ключем без ідентифікатора профілю.
- **Плитки як окремі блоки чи ряд у блоці «Основні показники»:** формат допускає обидва
  варіанти (блок `tiles` з однією чи кількома плитками).
- **Хто редагує:** рівень власника (оформлення модуля, як у «Редакторі модуля») і рівень
  профілю (таблиця й плитки користувача) — окремі шари.

## Дорожня карта

1. **Формат і валідатор** (цей документ). Поведінка застосунку не змінюється.
2. Плитки як описи: шість поточних карток ПС записуються в каталозі й дають той самий вигляд
   (перевірка знімками на синтетичних даних). Підрахунок виконує чистий `tiles-core.js`.
3. Конструктор порожньої таблиці ПС за каталогом (запис XLSX зі схемою на прихованому аркуші)
   і каталог плиток із переглядом та правкою.
4. Динамічні блоки в «Розташуванні блоків»: набір ідентифікаторів береться зі схеми.

Для РВ, ПВК, УДШВ і артилерії те саме робитиметься після ПС, на тому самому двигуні.
