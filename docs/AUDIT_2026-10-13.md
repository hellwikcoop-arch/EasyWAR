# Аудит EasyWAR — 13 жовтня 2026

Ревізія: `main` @ `b2a069f` (версія 1.0.7). Звіт не закомічено; файл лежить у `docs/`
як робочий документ власника.

## 1. Обсяг і метод

**Перевірено**

- Rust-ядро (`src-tauri/src`, 17 619 рядків, 52 команди `#[tauri::command]`), усі
  8 міграцій, Signal-підсистема (7 модулів), оновлювач, резервні копії/відновлення.
- Фронтенд: усі ES-модулі `src/*.js` і `src/public/*.js`; три великі legacy-сторінки
  (`index.html` 1,1 МБ, `air.html` 2,6 МБ, `rocket.html` 11,3 МБ) — лише цільовими
  пошуками (sink-и XSS, зовнішні хости, `postMessage`, сховища, ключі).
- Конфігурація Tauri (CSP, capabilities, ACL-семантика перевірена у вихідному коді
  `tauri 2.11.6`), CI (`desktop-build.yml`), скрипти випуску, публічний репозиторій
  `easywar-releases` (список релізів, розміри артефактів, `latest.json`).
- Залежності: `npm audit`, `npm outdated`, `cargo audit` (RustSec), MSRV.
- Історія git: 243 коміти, 1 215 текстових blob-ів просканувано на токени, приватні
  ключі, телефони `+380…`, URI прив'язки Signal; перевірено, чи потрапляли в історію
  XLSX/CSV/SQLite/.env.
- Ліцензії 3D-моделей і шрифтів, відповідність документації коду.

**Виконано:** `cargo test`, `cargo clippy --all-targets --all-features -D warnings`,
`cargo fmt --check`, `npm run test:unit`, `npm run build` (Linux, Node 22.22, Rust 1.97).

**Не перевірено:** збірка та запуск на macOS/Windows, робота з реальним `signal-cli`,
ручне тестування UI, построковий перегляд ~15 тис. рядків inline-скриптів legacy-сторінок
(лише цільові пошуки), налаштування GitHub (захист гілок, Dependabot alerts).

## 2. Підсумок

Загальний стан — **добрий для проєкту такого розміру**, з кількома структурними
ризиками, які варто закрити до ширшого розповсюдження.

Сильні сторони, підтверджені кодом і тестами:

- Жодна Rust-команда не приймає шлях у файловій системі з webview: усі шляхи — з
  нативних діалогів або з прив'язок профілю; запис у вибрані користувачем місця
  йде через тимчасовий файл + `persist_noclobber` (два винятки нижче).
- Увесь SQL параметризований; таблиці провенансу INSERT-only в коді та захищені
  тригерами в схемі; переходи статусів перевірки контролюються в Rust.
- Резервна копія / відновлення / міграції: блокування екземпляра (fs2), маркери,
  перевірка цілісності, відкат, тести на переривання — зроблено ретельно.
- Оновлювач: адреса лише під час збірки за тегом, підпис minisign перевіряється і в
  CI, і в застосунку; копія бази перед оновленням.
- Signal: deny-by-default в Rust на кожному повідомленні, лише loopback, обмежені
  буфери, без запуску процесів, без логування вмісту.
- Фронтенд: у перевірених шляхах рендеру даних (XLSX, Signal, SQLite, KML) —
  `textContent`; `innerHTML` лише для константних SVG; немає CDN, `eval`, зовнішніх
  бібліотек у HTML; онлайн-карти й dimap вимкнені за замовчуванням і за згодою.
- У репозиторії та його історії не знайдено секретів, реальних операційних даних,
  телефонів. Базові таблиці порожні, фікстури синтетичні.

Головні ризики (деталі в розділі 4):

1. **CSP = null + сирий IPC-міст у iframe + 52 команди без ACL** — будь-яка майбутня
   ін'єкція в legacy-код дорівнює повному доступу до команд і необмеженій
   ексфільтрації (сьогодні конкретного sink-а не знайдено).
2. **CI не запускає Rust-тести, clippy і fmt.** 180 Rust-тестів виконуються лише
   локально; один із них нестабільний (падає ~5 з 8 запусків), і цього ніхто не бачить.
3. **Процес випуску розходиться з власними правилами:** чек-лист релізу — NO-GO,
   а в публічному репозиторії опубліковано ≥16 версій, 5 із них за 17 годин 8–9 жовтня;
   письмових рішень-винятків у репозиторії немає.
4. Операційні дані поза SQLite і резервними копіями: ключ Planet у `localStorage`,
   повна копія таблиці «НАШІ ВТРАТИ» та геодані зон у IndexedDB; «файл для телефона»
   з таблицею без шифрування.
5. Команда `write_profile_database` перезаписує робочу таблицю будь-якими байтами
   без валідації та без попередньої копії.
6. Пошкоджена база = застосунок мовчки не стартує (ланцюжок `expect()` до створення
   вікна), а задокументований шлях відновлення недосяжний.

## 4. Знахідки

Шкала: **Високо** — потребує дії до наступного релізу; **Середньо** — у найближчому
циклі; **Низько** — за нагоди; **Інфо** — для відома. Критичних знахідок немає.

### Високо

**H1. Структурний ризик: CSP `null`, повний IPC-міст у кожному iframe, усі 52
команди доступні з webview.**
`src-tauri/tauri.conf.json` (`"csp": null`), `src/air.html:18-31`
(`easywar-desktop-frame-bridge` копіює `__TAURI_INTERNALS__` у кадр),
`src/presentation-ui.js:40`, `src/index.html:716-720` (iframe без `sandbox`),
`src-tauri/build.rs` (без ACL-маніфесту). Підтверджено в `tauri-2.11.6/src/webview/mod.rs:1823`:
без маніфесту команди застосунку не перевіряються для локального походження
(віддалені origin, як-от dimap.live, блокуються). Наслідок будь-якої майбутньої DOM-ін'єкції
в ~15 тис. рядків legacy-скриптів: читання/перезапис прив'язаних XLSX, SQLite-модель,
сирі тексти Signal, видалення профілів, встановлення оновлення, і — оскільки немає
`connect-src` — відправлення чого завгодно на будь-який хост.
*Рекомендація:* ввести CSP, що лишає `'unsafe-inline'` для legacy-скриптів, але
обмежує `default-src 'self'`, `connect-src 'self' <хости плиток>`, `img-src 'self' data:
blob: <хости плиток>`, `frame-src https://dimap.live`, `object-src 'none'`; замінити
копіювання `__TAURI_INTERNALS__` на фасад із потрібними кожному модулю командами;
далі — ACL-маніфест (`tauri_build::Attributes::app_manifest(AppManifest::new().commands(..))`)
з явним allow-list.

**H2. CI не виконує Rust-перевірки.**
`.github/workflows/desktop-build.yml`, job `checks`: лише `release_version.mjs`,
`npm run test:unit`, `npm run build`. `cargo test`, `cargo clippy`, `cargo fmt` є в
`docs/RELEASE_CHECKLIST.md` §2, але не в CI. Наслідки: нестабільний тест (M2) невидимий;
10 розбіжностей fmt накопичилися; немає `cargo audit`/`npm audit`, Dependabot
(`.github/dependabot.yml` відсутній), CodeQL. Toolchain `stable` не зафіксований
(`rust-toolchain.toml` немає).
*Рекомендація:* додати до job `checks` три cargo-кроки (кеш уже є), `npm audit --omit=dev`
і `cargo audit` (з ignore для RUSTSEC-2023-0071), Dependabot для npm/cargo/actions.

**H3. Випуски публікуються всупереч власним правилам випуску.**
`README.md` і `docs/RELEASE_CHECKLIST.md`: «Production distribution remains NO-GO»,
публікація технічного випуску — лише за письмовим рішенням-винятком (`docs/UPDATES.md`).
Факт: у публічному `hellwikcoop-arch/easywar-releases` опубліковано (не чернетки)
щонайменше 16 версій від 0.6.0 до 1.0.7; 1.0.3–1.0.7 — п'ять версій за 17 годин
(8 жовтня 20:45 → 9 жовтня 13:25 UTC). У `docs/releases/*.md` немає жодного запису
про рішення, ризик, власника й відкочування. Чернетки 0.8.0 і 0.9.0 лишилися
«untagged». Усі PR відкриває і зливає один акаунт без незалежного рев'ю; 150 із 243
комітів авторства Claude. `README.md` досі каже «Current milestone: 0.5».
*Рекомендація:* або вести реєстр рішень-винятків (хоч один файл `docs/releases/DECISIONS.md`),
або чесно переписати чек-лист під фактичний «технічний» режим; обмежити частоту
випусків (кожен — 127–259 МБ завантаження для кожної встановленої копії, див. M9).

### Середньо

**M1. Будь-який користувач Signal (не лише дозволений) може зупинити сеанс прийому
одним нетекстовим конвертом.** `src-tauri/src/signal_ingest.rs:106-123` перевіряє форму
конверта (`timestamp`, `dataMessage`, непорожній `message`) **до** allowlist;
`signal_session.rs:60-64` перетворює на `Ignored` лише `SourceDenied`, усі інші помилки
(`InvalidEnvelope`, дублікат у БД) завершують сеанс. У реальному потоці signal-cli
квитанції доставки, typing, sync-повідомлення зв'язаного пристрою, фото без підпису,
реакції не мають `dataMessage.message` — кожне з них зупиняє сеанс; навіть відповідь
на власний `/ping` провокує квитанцію. `docs/SIGNAL_INTAKE.md:105-108` стверджує
протилежне. *Рекомендація:* `InvalidEnvelope` і дублікат — рахувати як `ignored`,
фатальними лишити лише помилки БД; додати синтетичний тест із квитанцією/typing/sync
перед дозволеним текстом.

**M2. Нестабільний Rust-тест.** `signal_session::tests::bounded_session_persists_allowed_synthetic_notification`
(`src-tauri/src/signal_session.rs:448`): синтетичний loopback-демон очікує рівно два
cleanup-запити (`send`, `unsubscribeReceive`) у фіксованому порядку; при гонці клієнт
чекає 8 с тайм-ауту, сервер отримує закрите з'єднання («synthetic request ended before
headers») і сеанс завершується `UnsubscribeFailed`. Падіння 5 із 8 запусків тут.
*Рекомендація:* зробити синтетичний сервер стійким до порядку/повторів, прибрати
залежність від реальних тайм-аутів (ін'єкція `Duration`), після чого увімкнути в CI (H2).

**M3. `write_profile_database` перезаписує операційну таблицю без валідації й
без попередньої копії.** `src-tauri/src/lib.rs:490-520`: перевірка лише `len ≤ 64 МіБ`
і префікс `PK`, далі атомарний rename поверх робочого XLSX. Помилка серіалізації у
фронтенді (порожня/обрізана книга) або ін'єкція (H1) знищує єдину робочу копію
журналу. *Рекомендація:* перед `persist` відкрити байти `zip`/`calamine` і вимагати
потрібний аркуш; тримати ротовану копію `<назва>.easywar-prev.xlsx` поруч.

**M4. Пошкоджена база → застосунок мовчки не стартує.** `src-tauri/src/lib.rs:1161-1180`:
`expect()` на блокуванні екземпляра, відновленні sidecar-файлів, запитаному
відновленні й міграції виконуються до `tauri::Builder`; на Windows (`windows_subsystem`)
консолі немає. Повна `integrity_check` на кожному запуску (`migration_startup.rs:65`)
робить будь-яку непоправну сторінку або затримку попереднього екземпляра >5 с
причиною паніки. Задокументований in-app шлях відновлення в цей момент недосяжний,
а `BACKUP_AND_RECOVERY.md` забороняє чіпати `easywar.db` вручну.
*Рекомендація:* нативне повідомлення про помилку та варіант «відкласти пошкоджену базу
в `easywar.db.damaged-<час>` і стартувати порожнім», щоб UI відновлення став доступним.

**M5. Ключ Planet — у `localStorage` відкритим текстом і в query-рядку URL плиток.**
`src/air.html` (`store('aviahub.planetKey')`, `…/gmap/z/x/y.png?api_key=…`), дубль у
`rocket.html`. Ключ читає будь-який скрипт webview, він лежить у профілі WebView
поза резервними копіями й блокуванням профілю, потрапляє в логи Planet/проксі.
*Рекомендація:* зберігати в Rust (keychain/файл 0600), плитки отримувати Rust-командою з
`Authorization: Basic`; мінімум — не зберігати в `localStorage`.

**M6. Операційні дані поза SQLite, резервними копіями і блокуванням профілю.**
IndexedDB `avtovvid` → `own-losses-<pvk|dshv>` = **повні байти XLSX «НАШІ ВТРАТИ»**
(`src/own-losses-dashboard.js:92`); IndexedDB `aviahub-dash` → зони з KML/GeoJSON,
лінія бойового зіткнення, базова карта з координатами; `localStorage`
`easywar.presentation.uafsans` = base64 шрифтів. Усе це відкритим текстом у каталозі
WebView, не входить у `create_local_backup`, лишається після `lockLocalProfile`.
*Рекомендація:* перенести в SQLite через команди або очищати при блокуванні; описати
залишки в `USER_GUIDE.md`; у документації додати рекомендацію FileVault/BitLocker
(зараз жодної згадки про шифрування диска).

**M7. «Файл для телефона» з вбудованою таблицею — без шифрування, пароля і строку дії.**
`src-tauri/src/phone_export.rs:104-137`, `script/standalone-embedded-table.js`. Опція
вимкнена за замовчуванням і з попередженням (добре), але файл із повною таблицею
(усі рядки, не лише затверджені) пересилається месенджерами. *Рекомендація:*
необов'язкова парольна фраза (PBKDF2 + AES-GCM через WebCrypto, уже доступний у
сторінці) і банер із датою знімка/строком.

**M8. Вразливі/застарілі парсери XML.** `quick-xml = "=0.31.0"` і `calamine = "=0.26.1"`
зафіксовані точно; `xlsx_export.rs:344-642` розбирає XML еталонної книги цим
`quick-xml`, `calamine` — усі імпортовані XLSX. Дві high-поради RustSec (квадратичний
час, необмежена пам'ять) = DoS від спеціально сформованої книги (локальний застосунок,
файл обирає користувач — тому не вище «середньо»). Додатково `xlsx_export.rs:262-286`
читає кожен ZIP-запис без ліміту розпакованого розміру (zip-bomb), `column_number`
(`:986-990`) — неперевірене множення. *Рекомендація:* оновити до `calamine 0.36` /
`quick-xml 0.42` (зміни API), обмежити розпакований розмір запису, `checked_mul`.

**M9. Розмір артефактів і репозиторію.** Кожне оновлення: macOS 259 МБ, Windows
127–128 МБ; 119 МБ із них — 3D-моделі `.glb`, які не змінюються між більшістю версій.
За 9 жовтня встановлена копія мала б завантажити ~1 ГБ. Репозиторій: pack 150 МБ,
`.glb` перекомічуються цілими (HIMARS — 3 версії по 11–15 МБ), `rocket.html` 11 МБ
має 25 версій в історії; Git LFS не використовується, `.gitattributes` немає.
*Рекомендація:* винести моделі в окремий ресурс (завантаження на вимогу або окремий
рідко оновлюваний пакет), перевести бінарні активи в LFS, не випускати кілька версій
на день.

**M10. Документація розходиться з кодом.**
- `docs/DATABASE.md:240-243` — «перевірка підпису/завантаження не реалізовані» (є
  в `app_update.rs`); `:13-23, :42` зупиняються на міграції 0006 (є 0007/0008 з
  `pvk`, `dshv`, `*_losses`); `:6` описує `tauri-plugin-sql` як керівника бази.
- `docs/SIGNAL_INTAKE.md:70-71` — «операція не зареєстрована як команда» (зареєстрована
  `run_signal_receive_session`); `:105-108` — див. M1.
- `docs/ARCHITECTURE.md:66-67` — таблиці `signal_messages`, `attachments` не існують.
- `README.md`, `docs/PROJECT_CONTEXT.md` — «milestone 0.5»; розділ «Repository layout»
  не згадує `artillery.html`, `viewer.html`, більшість `src/*.js`.
- `script/verify_macos_bundle.sh:6` — жорстко прошито `EasyWAR_0.5.0_aarch64.dmg`,

- `src-tauri/Cargo.toml` `rust-version = "1.77.2"`, тоді як `reqwest 0.13.5` вимагає 1.85.

### Низько

**L1.** Деструктивні/побічні команди без нативного підтвердження, доступні зі скрипту:
`finalize_local_restore` (видаляє `.restore-previous` — єдину копію для відкату),
`cancel_staged_restore`, `apply_staged_restore_and_restart`, `install_app_update`
(перевірка підпису є, але «підтвердження користувача» живе лише в JS),
`delete_local_profile` для профілю без пароля. `src-tauri/src/lib.rs:539-550, 867-881,
933-965`. Рекомендація: `app.dialog().message().blocking_show()` перед дією.

**L2.** `set_local_profile_password` не прив'язана до сесії: для профілю без пароля
`verify_password(id, "")` істинний, тож скрипт може поставити пароль будь-якому
профілю (`lib.rs:204-227`, `local_profiles.rs:329-333`). Вимагати активний
розблокований профіль.

**L3.** `save_presentation` (`lib.rs:311-318`) і `export_phone_file` (`phone_export.rs:140-164`)
дописують розширення **після** діалогу: якщо користувач обрав `report`, а `report.pptx`
існує — файл перезаписується без запитання; `save_presentation` пише `std::fs::write`
неатомарно. Використати той самий шаблон `NamedTempFile` + `persist_noclobber` + `sync_all`.

**L4.** Передперевірка відновлення (`restore.rs:643-678`) вимагає об'єкти схеми лише до
v4; копія v8 без `local_profile_details`/`local_profile_tables` проходить і ламає екран
профілів після свопу. Виводити список обов'язкових таблиць із `database.rs` за версією.

**L5.** Необмежене накопичення повних незашифрованих копій бази: `easywar.db.pre-migration-*`
(до 1024, `migration_startup.rs:134-182`) і `backups/EasyWAR-before-update-*`
(`app_update.rs:137-147`); нічого не чистить. Після першого запису прив'язаний XLSX
отримує режим 0600 тимчасового файлу (`lib.rs:526-534`) — ламає спільні теки на macOS.

**L6.** Ідентифікатор рецензента приходить із webview (`lib.rs:732-755`,
`repository.rs:1231-1237`); з появою паролів у профілів його варто виводити з
`ProfileSession` + `display_name`.

**L7.** `desktop_shell.rs:28-31`: `is_app_url` вважає внутрішнім будь-який
`http(s)://localhost:*` / `127.0.0.1:*` і в релізі — навігація на порт signal-cli
відкриється у вікні застосунку (IPC для такого origin заблоковано, тож лише спуфінг UI).

**L8.** Signal: будь-яке повідомлення, що починається з `/`, вважається командою і не
зберігається (`signal_commands.rs:21-41`, `signal_session.rs:66-81`) — доповідь
«/12.10 …» від дозволеного відправника тихо губиться.

**L9.** Signal: демон — неавтентифікований корінь довіри на «людному» порту
`127.0.0.1:8080` без handshake `version`; будь-який локальний процес, що займе порт,
буде сприйнятий як signal-cli і зможе підкинути конверти з дозволеним `sourceUuid`
у чергу NEW (ручна перевірка лишається). Транспорти `Tcp`/`UnixSocket` приймаються
конфігом, але повертають `UnsupportedTransport`.

**L10.** Signal: URI прив'язки `sgnl://linkdevice?...` (короткоживучий секрет) ходить
через webview туди й назад (`lib.rs:653-672`, `signal-settings.js:431-446`); ніде не
логується і не зберігається, але краще тримати в `tauri::State` за одноразовим токеном.

**L11.** Signal: повний сирий конверт зберігається дослівно й назавжди (`raw_payload_json`),
без шляху очищення всередині застосунку; документувати, що вкладення пише сам
signal-cli у свій каталог поза контролем EasyWAR.

**L12.** `tauri-plugin-sql` зареєстрований із `preload` і міграціями (`lib.rs:1185-1189`,
`tauri.conf.json`), але жодна JS-сторінка його не використовує і capability не дає
`sql:*`: другий пул до тієї ж бази, повторна перевірка `_sqlx_migrations`, зайва npm-залежність.
Латентний ризик: одна «виправна» правка `sql:default` у capability відкриє сирий SQL
(включно з `DROP TRIGGER`) з webview. Прибрати плагін і залежність.

**L13.** dimap.live вбудовується живим iframe у чутливе вікно (`air.html`, за згодою,
`sandbox` без `allow-top-navigation`); безпечніший шлях «відкрити в системному браузері»
уже є. Згода на онлайн-карти зберігається і джерело плиток відновлюється при
наступному старті без повторного запитання.

**L14.** Пароль «Редактора модуля»: один хеш для всіх інсталяцій, у VCS і в публічних
збірках; блокування на 60 с після 5 спроб лежить у `localStorage`. Документація чесно
називає це захистом лише UI. `set_editor_password.mjs` приймає пароль зі змінної
середовища (історія shell). Варіант: генерувати хеш під час збірки з секрету CI.

**L15.** У production-діалозі Signal лишилася синтетична «Черга Signal — демонстрація»
з кнопками схвалити/відхилити (`signal-settings.js:92-188`) — плутає в бойовому інструменті.

**L16.** `npm audit`: `image-size` через `pptxgenjs 4.0.1` (DoS при розборі зображень
JXL/HEIF/ICNS; торкається лише зображень, які користувач сам додає до презентації);
`source-map-js` — лише dev. Стежити за виправленням у `pptxgenjs`.

**L17.** `cargo fmt --check` — 10 розбіжностей; `rust-toolchain.toml` відсутній, CI
бере плаваючий `stable`.

**L18.** Ліцензії: файлу `LICENSE` немає; 4 моделі (Р-27, Р-77, Х-29, КАБ-500Л) —
CC BY-NC-SA 4.0 з коректно задокументованим обмеженням; `src/fonts/UAFSans.ttf` без
файлу ліцензії в репозиторії. `CREDITS.md` покриває всі 29 моделей.

**L19.** Особисте посилання `https://signal.me/#eu/…` «Написати розробнику» у лаунчері
(`index.html:712`) — OPSEC-міркування для військового інструменту; прибрати з
production-збірок.

### Інфо

**I1.** `PRAGMA foreign_keys = ON;` у кожній міграції не діє: sqlx виконує міграцію в
транзакції, де SQLite ігнорує цю прагму; реальне увімкнення — `.foreign_keys(true)` в пулах.

**I2.** Повна `integrity_check` + `foreign_key_check` на кожному старті (O(розмір бази));
пул застосунку `max_connections(1)`, тож `VACUUM INTO`, сеанс Signal і всі команди
серіалізуються на одному з'єднанні.

**I3.** `configured_endpoint()` (`app_update.rs:95-105`) не вимагає `https`; підпис
захищає цілісність, але не приватність метаданих запиту.

**I4.** Дублювання коду: 7 копій `h()`/`el()` у JS-модулях + по 2 у кожній HTML-сторінці;
форматування дат у 6 файлах, чисел — у 5, IndexedDB-обгортки — у 4; `air.html` і
`rocket.html` містять майже ідентичні копії коду карт/плиток/KML/dimap/сховища — кожну
правку треба робити двічі. У Rust: `sibling_path`/`sync_parent`, `normalize_label`,
`optional_string` продубльовані; сім різних тестових фікстур «застосувати міграції»
застосовують різні підмножини; `database::migrations()` і `EMBEDDED_MIGRATOR` — два
джерела істини, узгоджені лише тестом. Функції >200 рядків: `finalize_signal_review`
(~290), `stage_xlsx_batch` (~225), `initializeSignalSettings` (679), `initializeLocalProfiles` (~725).

**I5.** Покриття тестами. Rust: `#[cfg(test)]` в усіх модулях; прогалини — шар команд
(перевірка сесії профілю) не тестується зовсім, `open_external`, `configured_endpoint`,
v5–v8 у передперевірці відновлення. JS: без прямих тестів `artillery-app.js`,
`local-profiles.js`, `backup.js`, `phone-export.js`, `own-losses-dashboard.js`,
`presentation-ui.js`, `presentation-pdf.js`, `signal-settings.js`, `launcher-tools.js`,
`module-editor.js`; legacy-сторінки — лише текстові контракти.

**I6.** Збірка Vite попереджає, що `module-editor-core.js`/`module-editor.js` не
бандляться без `type="module"` — очікувано (класичні скрипти з `public/`), але
варто зафіксувати коментарем, щоб не «виправили».

## 6. Обмеження цього аудиту

- Linux-контейнер: збірка Tauri-бандлів, запуск вікна, Gatekeeper/SmartScreen,
  реальний `signal-cli` не перевірялися.
- Legacy-сторінки (`air.html`, `rocket.html`) перевірено цільовими пошуками, не
  повним читанням; відсутність sink-ів XSS стверджується для знайдених шаблонів
  (`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`,
  `new Function`, `javascript:`), а не для всього коду.
- Налаштування GitHub (захист гілки, обов'язкові перевірки, Dependabot alerts,
  видимість `easywar`) із контейнера не видно; висновки щодо процесу зроблено з
  історії PR і релізів.
- Нестабільність тесту M2 відтворена в цьому середовищі; частота на macOS/Windows
  може відрізнятися.
