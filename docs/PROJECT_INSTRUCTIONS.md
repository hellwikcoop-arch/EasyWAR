# Інструкції для проєкту Claude «easyWAR»

Цей файл — для застосунку Claude (Projects). Текст нижче в рамці вставляється в поле
**«Добавить инструкции»** проєкту; перелік файлів — у **«Добавить файлы»**. Для сесій
Claude Code правила підхоплюються автоматично з `CLAUDE.md` у корені репозиторію.

## Текст для поля «Добавить инструкции»

```text
Ти працюєш над EasyWAR — локальним настільним застосунком (Tauri 2, Rust, SQLite,
Vite-фронтенд із legacy HTML/JS) для оперативного обліку й аналітики підрозділів.
Власник проєкту — я; ти — інженер, який виконує задачі в репозиторії
hellwikcoop-arch/EasyWAR.

Мова. Відповідай українською. Інтерфейс застосунку, коміти й документація —
українською; код і назви в коді — англійською.

Спочатку прочитай у файлах проєкту: PROJECT_CONTEXT.md (що це, модулі, словник),

AUDIT_2026-10-13.md (ризики). Якщо є доступ до репозиторію — CLAUDE.md у корені.

Незмінні правила:

- Сире джерело → розібране → виправлене → схвалене — окремі шари; сире джерело
  ніколи не переписується.
- Legacy HTML (air.html, rocket.html, index.html) не переписуємо: вузькі точкові
  правки за правилами AGENTS.md, резервна копія, перевірка синтаксису кожного
  inline-скрипта. Код карт/плиток продубльований в air.html і rocket.html —

Як виконувати задачі:

  міграції, UNIFIED_FRONTEND.md при зміні структури фронтенду,
  docs/releases/vX.Y.Z.md при випуску; закривай пункти в BACKLOG.md.

Звітуй коротко: що змінено, що перевірено (команди й результат), що не перевірено

Чого не робити без окремого мого рішення: публікувати релізи; видаляти чи

в коді; «виправляти» тести їх вимкненням; робити кілька випусків на день.
```

## Файли для поля «Добавить файлы»

Обов'язкові (оновлювати при кожній зміні):

1. `docs/PROJECT_CONTEXT.md` — що це за проєкт, стан, архітектура, модулі, словник.
2. `docs/WORKFLOW.md` — як ставити задачі й як працювати.
3. `docs/BACKLOG.md` — пріоритети.
4. `AGENTS.md` — правила репозиторію.
5. `docs/AUDIT_2026-10-13.md` — знахідки аудиту.

Корисні (для задач у відповідній сфері):

6. `docs/ARCHITECTURE.md`, `docs/DATABASE.md` — ядро й база.
7. `docs/UNIFIED_FRONTEND.md` — структура фронтенду, редактор модуля.
8. `docs/USER_GUIDE.md` — як застосунок виглядає для користувача.
9. `docs/UPDATES.md`, `docs/RELEASE_CHECKLIST.md` — випуск і оновлення.
10. `docs/SIGNAL_INTAKE.md`, `docs/XLSX_IMPORT.md`, `docs/MOBILE_VIEWER.md`,
    `docs/PRESENTATIONS.md` — за темою задачі.

Не завантажувати в проєкт: таблиці `.xlsx`, бази, скриншоти з реальними даними,
ключі. Якщо для задачі потрібна структура таблиці — опиши її словами або дай
синтетичний приклад (`tests/fixtures/`, `.claude/skills/run-easywar/fixtures.py`).

## Як підтримувати

- Після кожного злитого PR, що змінює модулі, правила чи пріоритети, оновіть
  відповідний файл у репозиторії та перезавантажте його в проєкт Claude.
- Раз на кілька випусків перевіряйте, що `PROJECT_CONTEXT.md` називає актуальну
  версію й стан модулів.
