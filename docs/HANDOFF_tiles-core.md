# Передача: конструктор таблиць, Крок 2 (картки ПС → каталог)

Файл контексту для того, хто підхоплює роботу (j5). Стан на 2026-10-18, гілка `claude/tiles-core`.
Усе нижче — про репозиторій десктопного застосунку (`/home/claude/easywar`, Tauri 2), а не про
single-file `EasyWAR_HIMARS.html`. Коротко: що робимо, що вже зроблено й перевірено, що лишилося,
і які рішення власника вважати фіксованими.

## Що це за робота

Будуємо **конструктор таблиць із гнучким каталогом** — щоб користувач складав власні журнали
(стовпці, плитки, блоки дашборда) без прив'язки до конкретної предметної області. План із 4 кроків:

1. **Формат + валідатор каталогу** — ✅ зроблено й у `main` через гілку `claude/catalog-format`
   (коміт `574e1d0`). Формат `easywar.catalog`, перевірка, схема таблиці, вивід стовпців.
2. **Плитки як описи** — 🔸 поточний крок. Шість карток «Основних показників» модуля ПС
   (`src/air.html`) описано як вбудований каталог; підрахунок винесено в чисте ядро; сторінка малює
   картки з каталогу з **піксельно тим самим виглядом**. Детально нижче.
3. Порожня таблиця-конструктор + каталог плиток (XLSX зі схемою на прихованому аркуші, міграція SQLite).
4. Динамічні блоки в «Розташуванні блоків» + нові типи блоків `pivot`, `calendar`, вибір вигляду
   для `dynamics`; далі `histogram`, `timeline`. Рішення щодо типів віджетів уже записано
   (`docs/CATALOG.md`, розділ «Типи віджетів: що беремо»).

**Кроки 3–4 ще не авторизовані** — не починати без прямого «так» власника.

## Архітектура Кроку 2

Потік: **рядки таблиці → перехідник `ps-kpi.js` → ядро `tiles-core.js` (за описом із каталогу) → моделі → `kpiCard` малює**.

- **`src/catalog-core.js`** (розширено). Формат плитки отримав: `caption`, `ringLabel` (лише для
  `ring`), `info` (`{ text?, facts[≤4]{ label?, measure } }`), `hideWhenZero`. Міри: `days` (кількість
  діб періоду — лише як `per` і у фактах/extras, без відбору), `low` (мінімум за добу/тиждень/місяць
  серед періодів із записами), зважений/обмежений `top` («назва N · назва N»). `extras` отримали
  `per`, `icon`, `unit` (рядок або `{one,few,many,fraction?}`), `suffix`. `ring` приймає `share` або
  `count`+`filter` (значення = кількість, кільце = частка від усіх рядків). Нова експортна функція
  `catalogFinder(catalogs, who)`.
- **`src/tiles-core.js`** (нове, чисте — без DOM/мережі/сховищ/годинника/динамічного коду; є тест,
  що це стереже). Експортує `computeTile`, `computeTiles` і дрібні хелпери (`dayNumber`, `periodDays`,
  `formatInt`, `formatRatio`, `pluralForm`). Приймає перевірений каталог, id плитки й
  `{ rows, period:{from,to}, compare }`, повертає заморожену модель: `value`, `delta`, `bars|series|ring`,
  `extras`, `info`, `hidden`. `compare` обирає сторінка: `null | {kind:'previous',rows} | {kind:'halves',first,second}`.
- **`src/catalogs/ps-builtin.js`** (нове). Вбудований каталог ПС (шар `builtin`): список
  `list.ps-result` (Уражено/Пошкоджено/Не уражено/Не відомо), 5 стовпців (заголовки — з імпорту XLSX:
  `Дата`, `Тип боєприпасу`, `К-сть боєприпасів`, `Результат ураження`; `Відбій` виводиться з тексту,
  окремого заголовка немає), 6 плиток (`tile.ps-sorties`, `-munitions`, `-hit`, `-partial`, `-miss`,
  `-unknown`), блок `block.ps-kpis` (ряд плиток) і два блоки-цілі для кнопки «Докладніше»:
  `block.ps-ops` (журнал), `block.ps-mun` (боєприпаси). Плитка «Не відомо» має `hideWhenZero: true`.
- **`src/ps-kpi.js`** (нове). Перехідник без DOM. `toRecord(row)` зводить рядок парсера до запису за
  id стовпців. `buildCards(input, deps)` приймає `{rows, from, to, prevRows?, halves?, series, axis}` і
  `{mkDelta, colors, monthNames}` сторінки, повертає конфіги для `kpiCard` (приховані плитки відсіяно).
  Реєструє `window.PSKpi` лише коли є `window`.
- **`src/air.html`** (вузька правка у `renderAll`, ~рядок 5058). Блок складання карток замінено на:
  `if (window.PSKpi) { el.kpiGrid.append(...window.PSKpi.buildCards(...).map(kpiCard)); } else { …старий код… }`.
  Шапку/ефективність (`el.kpiEff`, `kh`) не чіпано. **Старий код лишено як запасний шлях** у гілці
  `else` (на випадок, якщо модуль не завантажився). Додано `<script type="module" src="./ps-kpi.js">`
  перед `sqlite-dashboard-source.js`.

## Що перевірено (на синтетичних даних)

- **JS-тести**: `node --test tests/catalog-core.test.mjs tests/tiles-core.test.mjs tests/ps-kpi.test.mjs`
  → **67 passed, 0 failed**.
- **Еталонний тест** (`tests/ps-kpi.test.mjs`): дослівні копії старих функцій сторінки (`agg`, `mkDelta`,
  складання `card`/`res`) порівняно з картками з каталогу на 400+ випадкових наборах (різні довжини
  періоду, кількості записів, набори результатів, записи без дати) — конфіги збігаються до символа.
  Набір охоплює всі гілки: приховану картку, попередній період, половини, відсутність бази.
- **Мутаційна перевірка**: навмисні зіпсуття валідатора (`catalog-core.js`), ядра (`tiles-core.js`) і
  каталогу ПС — кожне ловиться тестами.
- **Піксельна перевірка**: зібрав фронтенд **до** і **після** правки, прогнав `air.html` під Playwright
  (скіл `run-easywar`, синтетичні таблиці `fixtures.py` + крайній набір) на 9 сценаріях (весь період,
  30/7 днів, довільні діапазони, «За ефектом DPI», крайні випадки). PNG блоку `.kpi-grid`, `outerHTML`
  карток і текст шапки `.kh` — **побайтово ідентичні до/після**. Повторний «до»-прогін теж побайтово
  збігся (рендер детермінований). Консоль без помилок.
- Синтаксис усіх 5 inline-скриптів `air.html` — чистий (`new Function` над кожним).
- Збірка: `vite build` проходить (33 с).

  `histogram`, `timeline`; відкладаємо gauge і Sankey; відхиляємо Deck.gl/Mapbox, Handlebars,
  декоративні графіки.
- Дані доповідей — реальні бойові: нічого не домальовувати, не мапити старі авіаційні категорії
  результатів у нові без прямих підстав. У репозиторій/тести — лише синтетичні дані.
