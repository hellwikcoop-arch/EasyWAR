# ADR: криптопрофіль і ідентичність колективу

**Статус:** Запропоновано, чернетка до етапу C2a (21.10.2026). Не затверджено власником. Нових
залежностей не додано, `Cargo.toml` і `Cargo.lock` не змінено.  
**Етапи:** C2a (цей ADR + перелік крейтів), C2, C2p.  
**Пов'язане:** [`COLLECTIVES_PLAN.md`](../COLLECTIVES_PLAN.md) §6, К4, К9, Q10б;
[`plans/2026-10-21-easywar-accounts-sync.md`](../plans/2026-10-21-easywar-accounts-sync.md) A5;
рев'ю J3, розділи 1.2 (C06) і 3.

## Контекст

К9: перелік нових крипто-крейтів подається перед C2 і затверджується власником окремо. Уже є
`chacha20poly1305`, `hkdf`, `hmac`, `sha2`, `argon2`, `zeroize` (бібліотека «Офісу»). Бракує
підписів, обміну ключами, PAKE і канонічного кодування.

## Рішення (пропоноване; усі назви — кандидати для огляду, не схвалені)

| Потреба | Кандидат | Наявне |
|---|---|---|
| Підпис учасника й пристрою | Ed25519 (`ed25519-dalek`) | — |
| Обгортка ключа епохи для учасника | HPKE (RFC 9180, крейт `hpke`) або X25519 (`x25519-dalek`) + HKDF + ChaCha20-Poly1305 | HKDF, ChaCha20-Poly1305 |
| Шифрування операцій | XChaCha20-Poly1305 | `chacha20poly1305` |
| PAKE для вступу | CPace або SPAKE2 | — |
| Канонічне кодування для підпису | детермінований CBOR або фіксована бінарна схема з версією | — |
| Захист секретів профілю | Argon2id від пароля профілю | `argon2` |
| Затирання секретів | `zeroize` | є |

Ідентичність: ключ учасника (на профіль у колективі) і ключ пристрою, підписаний ключем
учасника; ID учасника — відбиток публічного ключа (§6). Не виводити з MAC/IMEI/серійних номерів;
не використовувати як ID лічильника К11. Ключі «Офісу» і ключі колективу розділені контекстом
HKDF.

Обов'язково зафіксувати в C2a: версію протоколу; AAD = усі відкриті поля заголовка; відкритими
йдуть лише випадкові ID, епоха, версія протоколу й криптографічні параметри (К4, AC24), **без
`class_hint`**; чи дозволене відкрите `expiry` — JE-16; політику nonce; anti-replay (журнал
`op_id` + digest); test vectors, однакові на Windows і macOS (G06); помилки без витоку деталей.
Сховище секретів (системне чи файл з Argon2id) — JE-18, у межах P1.

## Наслідки

Зміна `Cargo.toml`/`Cargo.lock` — одним виконавцем після JE-15, з `cargo audit` у CI.

## Відкрите для власника

JE-15, JE-16, JE-18 (рев'ю J3, розділ 5).

## Перевірки (лише синтетичні)

Вектори; зміна байта шифротексту, заголовка чи підпису → відмова; невідома епоха; пошкоджена
обгортка; відкликаний автор з backdated `client_time`; G06, G11.
