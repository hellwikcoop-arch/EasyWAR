# ADR: Local-first із дозволеними хмарними сервісами та E2EE обміном

**Рішення власника (JE):** 14.11.2026. **Зафіксовано:** 15.11.2026.
**Статус:** архітектурне рішення; **не є дозволом увімкнути WAN або завантажувати реальні дані**.
**Пов'язане:** [ARCHITECTURE.md](../ARCHITECTURE.md), [network-and-secret-boundaries.md](network-and-secret-boundaries.md), [collective-crypto.md](collective-crypto.md), [collective-store-forward.md](collective-store-forward.md), [collective-sync-policies.md](collective-sync-policies.md).

## Рішення

1. **Локальне джерело істини.** Робочі записи, SQLite, документи, EasyFLY, історія, їхні похідні та ключі шифрування зберігаються і опрацьовуються на пристрої власника. Редагування, перегляд і експорт локальних даних не залежать від мережі, хмарної підписки чи доступності сервера.
2. **Хмарні платформи дозволені.** Перевірені API, сервери й сховища можна використовувати для доставки довідкових/публічних даних, оновлень, автентифікації сервісів, майбутнього ліцензування, а також для передачі та тимчасового зберігання **лише клієнтськи зашифрованих** робочих пакетів і резервних копій. Провайдер не отримує матеріали для розшифрування.
3. **Явний обмін.** Надсилання користувацького запису іншому учаснику можливе лише після конкретного підтвердження відправника й перевірки авторитетних прав, членства, призначення, актуальності ключів та дозволеного транспорту **в Rust безпосередньо перед відправкою**. Дозвіл на один обмін не є загальним дозволом на синхронізацію всіх даних.
4. **Шифрування до мережі.** Пакет підписується й E2EE-шифрується локально для перевіреного адресата/колективу. Relay, R2 чи інший сервер бачить лише шифротекст, мінімальні службові поля та мережеві метадані, але не plaintext, секрети, ключі епох або імена з бази.
5. **Дані інших типів.** Не передавати зовнішнім AI API тексти з локальної бази, витяги, файли, історію чату з робочими даними або отримані з них промпти. Дозволені загальні запити без робочих даних, які користувач явно вводить і підтверджує. Локальна AI-модель може працювати з локальними даними за правами профілю. Координати для погоди/карт також можуть розкривати місце роботи — не передавати їх автоматично з приватних карт чи записів.
6. **Телеметрія/журнали.** Логи сервера, аналітика, URL, заголовки, crash-reporting та треті SDK не повинні містити відкриті робочі дані, ключі, приватні маршрути/координати чи їхні відтворювані похідні.
7. **Майбутній EasyFLY Pro.** Сервіс ліцензій може зберігати лише технічні entitlement-дані; втрата підписки не блокує читання, резервування й експорт власної бази. Реалізація монетизації відкладена.

## Межі довіри

| Зона | Дозволено | Заборонено |
| --- | --- | --- |
| Пристрій користувача | Повний робочий облік і розшифрування відповідно до прав | Прихована автоматична передача |
| API публічних сервісів | Запит на публічну довідку, погодний регіон без приватного походження, оновлення | Зовнішні запити, похідні від робочих записів, без окремого допуску |
| Relay / cloud storage | Ciphertext, opaque routing IDs, TTL, обсяг, технічні квитанції | Plaintext, ключі E2EE, довільний доступ до пакетів |
| Комп'ютер авторизованого одержувача | Розшифрування після перевірки членства, прав, підпису, replay/idempotency | Доступ від відкликаних учасників або некоректних пристроїв |

**Наскрізне шифрування не приховує всі метадані.** Провайдер може бачити IP, час, розміри пакетів і частоту звернень. Компрометація кінцевого пристрою, заражений клієнт і передача власником стороннього ключа залишаються окремими ризиками.

## Початковий зовнішній провайдер

**Кандидат для синтетичного пілота:** Cloudflare Workers (HTTP API) + D1 (мінімальна службова інформація) + приватний R2 (зашифровані байти). Вибір не означає vendor lock-in: зберігається транспортний контракт `put / fetch / ack` з `collective-store-forward.md`. За замовчуванням ніякого WAN-send, усі токени тільки у захищених налаштуваннях, не у фронтенді. До підключення пілота повторно перевірити free-tier, region/data residency, умови використання, обмеження ресурсу та threat model.

## Реальний стан коду на 15.11.2026

- `src-tauri/src/network_policy.rs` — **чиста** політика без мережевих викликів; не вбудована у всі фактичні мережеві команди. Потрібне незалежне приймання фактичних точок виклику; UI-прапорець не є авторизацією.
- `src-tauri/src/collective/send_gate.rs` — авторитетний допуск з політикою, де `wan_transport_accepted = false`, `base44_accepted = false`. Сам по собі цей ADR не змінює gate.
- `src-tauri/src/collective/relay.rs` / `relay_auth.rs` / `relay_node.rs` — частини локального store-and-forward та перевірок; не доказ готовності хмарного обміну.
- `src/workspace/profile-store.js` та `src-tauri/src/profile_data.rs` — профільні дані у desktop обслуговуються локально; browser fallback для preview не прирівнюється до захищеного desktop-сховища.
- `src/assistant/assistant-cloud.js` дозволяє надсилати набраний текст та історію онлайн-чату; це окремий ризик витоку. Перш ніж вважати канал сумісним із цим ADR, перевірити та відокремити лише безпечні загальні запити.

## Вимоги до приймання перед мережевим запуском

1. Інвентар усіх фактичних outbound-викликів: JS fetch/WebSocket, Rust HTTP/Socket, SDK, updater, external link, бекенд-логи; відкриті дані забороняються на рівні виконуваної команди/транспорту, не лише документа.
2. Інтеграційний тест з **синтетичними** документом, записом EasyFLY та таблицею: сервер/проксі бачить лише ciphertext й дозволені метадані; підмінені/прострочені повідомлення відхиляються.
3. Перевірка відкликаного учасника, неспівпадіння ключів, повторної відправки, втрати квитанцій, переповнення квоти, TTL і відновлення після перезапуску.
4. Незалежний security review і явне рішення JE перед відкриттям WAN. До того прапорці доступу лишаються вимкненими.
