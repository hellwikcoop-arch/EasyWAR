# G12: незалежна рецензія протоколу C2 (варіант Б) — чекліст

Статус: **відкрито.** Код C2 (наказ T-0017, гілка `claude/e8-c2-crypto-engine`) написано
й перевірено автоматично; рецензію **не автором коду** ще не виконано. До закриття чекліста
модуль `src-tauri/src/collective/` не має команд Tauri і не стоїть на жодному production-шляху
(C3b підключає його лише після G12 — ADR [`collective-crypto.md`](../../adr/collective-crypto.md), розділ 5).
Рецензента (C3 за чеклістом чи зовнішній) призначає JE. Реальних ключів і даних тут немає.

## Пункти рецензії (ADR розділ 5)

| № | Пункт | Де дивитися | Висновок рецензента |
|---|---|---|---|
| 1 | Обгортка ключа епохи відповідає HPKE-base (DHKEM-X25519 + HKDF-SHA256 + AEAD): ефемерний X25519, `kek = HKDF(shared, salt = collective_id ‖ epoch, info = easywar/collective/v1/epoch-wrap)`, AAD = увесь заголовок обгортки | `epoch.rs` (`wrap_with`, `kek`), вектор `epoch_wrap` у фікстурі | ☐ |
| 2 | Межі nonce: 192 біт з CSPRNG на кожен конверт і кожну обгортку; ротація епохи при відкликанні | `envelope.rs` (`EnvelopeHeader::new`), `epoch.rs`, `replay.rs` (`InMemoryMembership::revoke`) | ☐ |
| 3 | Контекстні мітки HKDF/підписів `easywar/collective/v1/*` не перетинаються з `easywar/library/v1/*` Офісу | `mod.rs` (`labels`), `office_library.rs` | ☐ |
| 4 | AAD конверта = усі відкриті поля (80 байтів: v, suite, collective_id, envelope_id, epoch, nonce, recipient_scope); зміна будь-якого → відмова | `envelope.rs` (`aad`, тест `every_open_field_is_authenticated`), node-тест | ☐ |
| 5 | `expiry` лише в payload (JE-16 а); `op_digest` не залежить від nonce/епохи/шляху | `envelope.rs` (`Payload::canonical`, `op_digest`), вектор `reencrypt` | ☐ |
| 6 | Дворівневий anti-replay: журнал `envelope_id`; `op_id → op_digest` (той самий — ідемпотентно, інший — `integrity_violation`) | `replay.rs` (`Journals`, `receive`), негативні вектори 1–2 | ☐ |
| 7 | Авторизація на `membership_seq` операції, не на `client_time`: пристрій дійсний, право запису на таблицю, епоха видана; `membership_seq` з майбутнього — відкладення, не відмова | `replay.rs` (`MembershipView`, порядок перевірок у `receive`), негативні вектори 3, 7 | ☐ |
| 8 | Правило відкликання: старий конверт після відкликання → відмова (б, робоче припущення) або карантин (а, перемикач `RevokedPolicy`); новий конверт з новою епохою від відкликаного → `EpochNotHeld` | `replay.rs`, негативні вектори 4–6; рішення JE-16 (а)/(б) | ☐ |
| 9 | Підпис пристрою: `verify_strict`, повідомлення = мітка ‖ канонічний payload; запис пристрою підписаний учасником (мітка ‖ pub ‖ member_id ‖ issued_at) | `identity.rs`, `envelope.rs` (`verify_signature`) | ☐ |
| 10 | Сховище секретів (Ф): Argon2id → майстер-ключ; окремий слот відновлення; зміна пароля перешифровує всі записи й видає новий ключ відновлення; ізоляція профілів (salt/AAD містять `profile_id`); знищення — zeroize + видалення файлу; аварія під час запису не псує попередній файл | `secret_store.rs` і його 7 тестів | ☐ |
| 11 | Zeroize: секрети (`EpochKey`, seed, майстер-ключ, KEK) затираються; `Debug` не друкує секретів | `epoch.rs`, `identity.rs`, `secret_store.rs` | ☐ |
| 12 | Кодек: фіксована бінарна схема big-endian з версією; зайві/обрізані байти → `Malformed`; жодного CBOR/JSON у підписаних байтах | `codec.rs` | ☐ |
| 13 | G06: ті самі вектори на Windows і macOS (`cargo test collective::`) | CI на тегах або локальний прогін власника | ☐ |
| 14 | RFC 9180 A.2 як контрольні вектори обгортки (пропозиція ADR) — власна обгортка не є HPKE побайтово (інші мітки), тому порівняння лише конструкції; рецензент фіксує, чи достатньо | ADR розділ 5 | ☐ |
