# Рішення про публікацію технічних випусків

Технічний випуск (macOS з ad-hoc підписом без нотаризації, Windows без Authenticode) не
відповідає розділам 7–8 [`RELEASE_CHECKLIST.md`](../RELEASE_CHECKLIST.md) і публікується
лише як виняток із правила GO / NO-GO за письмовим рішенням власника: хто прийняв ризик,
до якого строку та як відкотити (див. [`UPDATES.md`](../UPDATES.md), беклог P1-6).
Кожен випуск — окремий запис; записи лише додаються.

## 2.0.1 — 14.10.2026

- **Рішення:** опублікувати технічний випуск 2.0.1 як виняток. Прийняв власник проєкту
  (hellwikcoop-arch) у робочому чаті проєкту Claude 14.10.2026 («виправ та опублікуй»,
  потім «давай 2.0.1»); інтегратор — Claude (сесія Claude Code).
- **Що входить:** лінія 2.0 — інтерактивний довідник ПС і РВ (PR #49), 3D-довідники техніки
  (PR #50), довільне внесення (гілка `claude/manual-entry`), заставка, вхід за паролем
  (міграція 0009), офлайн-3D-карта, підривники Артилерії, спільний вигляд дашбордів
  (PR #48). Нотатки — `v2.0.1.md`.
- **Чому не 2.0.0:** тег `v2.0.0` було поставлено на коміт `c5df43c` з червоним `checks`
  (злиття PR #50 відкинуло зміни збірки), збірка не відбулася, артефактів немає. Тег не
  переносили; випуск пішов як 2.0.1 з виправленого `main`. Тег `v2.0.0` підлягає
  видаленню власником.
- **Ризик:** відсутність production-підпису (Gatekeeper/SmartScreen при першому ручному
  встановленні; оновлення з застосунку перевіряються ключем minisign і не блокуються);
  міграція 0009 не дає повернутися на 1.0.x без копії бази; сцени довідників і відео
  заставки перевірено лише в Chromium із програмним WebGL, не у вікнах macOS/Windows.
  Інсталятори для 2.0.1 збирає CI на тезі `v2.0.1`; ручного встановлення поверх копії зі
  старою синтетичною базою (крок 6 випуску) перед публікацією не проводили — власник
  прийняв цей ризик.
- **Строк:** до появи Apple Developer ID і Authenticode (беклог «Продукт»); після цього
  випуски йдуть через повний шлюз `RELEASE_CHECKLIST.md`.
- **Відкочування:** на машині користувача — відновити копію бази
  `backups/EasyWAR-before-update-*` (застосунок створює її перед оновленням) і
  встановити інсталятор 1.0.7 з `easywar-releases`; у репозиторії — зняти публікацію
  випуску 2.0.1 (повернути в чернетку), щоб `latest.json` знову вказував на 1.0.7.

## 2.2.0 — 19.10.2026

- **Рішення:** опублікувати технічний випуск 2.2.0 як виняток. Прийняв власник проєкту
  (hellwikcoop-arch) у робочому чаті проєкту Claude 19.10.2026: «Публікуй до тегу, скажеш
  коли створити тег», потім вибір «На main» для тегу й «Лишити в 2.2.0» для розділу «Офіс»
  (картки в чаті); інтегратор — Claude (сесія Claude Code).
- **Що входить:** каталог модулів дашборда і журнал хронометражу (міграції 0010, 0011),
  КОМБАТ із завантаженням моделі й вбудованим рушієм, безпечніший запуск і запис таблиць,
  обмеження спроб входу, виправлення за аудитом 2026-10-19 (PR #78), «Робоче середовище» →
  «Офіс» з прототипами EasyGreen, EasyDoc і EasySlide (PR #81–#84). Нотатки — `v2.2.0.md`.
- **Чому тег перенесено:** перший тег `v2.2.0` (коміт `734864322590527e2c412b1f14b43d4f63441fbd`)
  не зібрався на macOS (universal-збірка вимагала sidecar для кожної архітектури) і на Windows
  (перевірка рушія падала на кодуванні cp1252). Чернетку в `easywar-releases` не створено, нічого
  не опубліковано, артефактів немає, тож тег перенесено (виняток із P1-7, пункт 4, бо
  публікації не було). Виправлення — PR #85 і #80; тег поставлено на коміт `3aa506f`
  (злиття PR #86 з нотатками).
- **Перевірено:** на `main` до тегу зелені `cargo fmt`, `clippy -D warnings`, 357 Rust-тестів,
  949 JS-тестів, `npm run build`, `release_version.mjs`; пробний запуск `desktop-build.yml` на
  гілці з тим самим деревом пройшов повністю (checks, audit, macOS universal DMG, Windows MSI і
  NSIS, перевірка рушія в інсталяторі).
- **Ризик:** (1) F-01: редактори «Офісу» працюють у `<iframe>` того самого походження без
  `sandbox`, CSP вимкнено, тож їхній код технічно може викликати будь-які команди EasyWAR;
  рецензія J5 (C5.4) радить не поширювати збірки з цими редакторами й не працювати в них із
  чутливими документами; експлуатацію негативним тестом не перевірено; ізоляція (окремий
  webview з правами лише на `office_*`) — гілка `claude/office-isolation`, у `main` її немає;
  (2) немає production-підпису (macOS ad-hoc без нотаризації, Windows без Authenticode);
  (3) міграції 0010 і 0011 не дають повернутися на 2.1.1 без копії бази; (4) вікна macOS і
  Windows, вбудований рушій і «Офіс» у встановлених копіях, реальні ваги моделі вручну не
  перевірено; (5) крок 6 розділу «Випуск версії» (встановлення поверх копії зі старою базою)
  на момент запису не проведено.
- **Строк:** до наступного випуску, який має або містити ізоляцію F-01, або приховувати
  розділ «Офіс»; після цього ризик (1) знімається окремим записом.
- **Відкочування:** на машині користувача — відновити копію бази
  `backups/EasyWAR-before-update-*` (застосунок створює її перед оновленням) і встановити
  інсталятор 2.1.1 з `easywar-releases`; у репозиторії — зняти публікацію випуску 2.2.0
  (повернути в чернетку), щоб `latest.json` знову вказував на 2.1.1.
